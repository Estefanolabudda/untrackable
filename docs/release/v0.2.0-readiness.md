# Release readiness – Untrackable 0.2.0

Status: **approved by the maintainer (2026-11-11)** after their test on Chrome
for macOS (extension loads, Experimental can be activated, query parameters
are removed, OAuth `code`/`state` stays protected, further tested features
work). Released from the merge commit of PR #6 by the tag-triggered workflow.
Not published in the Chrome Web Store.

## Scope

Experimental mode – strip query parameters (opt-in), the context-menu actions
"Copy/Open link without query parameters", fragment-aware protection in
navigation rules (also benefits Clean/Strict) and review fixes. No new
permissions (install-time warnings unchanged).

## Reproducibility and the v0.1.0 checksum

- The published v0.1.0 asset has SHA-256
  `ee29d0c4f5db146d41609a135ae8a0baef2d2969e249092c061da1cd8d7baaea`. A clean
  build of tag `v0.1.0` (fresh clone, `npm ci`, `npm run package`) gives
  exactly this hash – the release is correct and reproducible.
- The different value reported before the release
  (`a7883c30…891534`) came from a **contaminated local build**: it ran in a
  helper worktree whose `node_modules` was a symlink into another checkout,
  so the workspace link `@untrackable/core` resolved to the v0.2 sources
  (reproduced: such a build contains Experimental code). Lesson: always build
  release candidates from a fresh clone with its own `npm ci`.
- Unix file modes are stored in the zip; a checkout/build with `umask 002`
  changed the hash. Since 0.2.0 `build.mjs` normalises modes (644/755) next to
  the fixed timestamps (2000-01-01, UTC) and sorted file list, and CI rebuilds
  with `umask 002` to require the same hash.

## Dependency audit

`npm audit` reported 10 moderate advisories, all one issue: `minimatch`
< 11.0.1 (GHSA-g3hv-75wg-m249, denial of service through crafted glob
patterns) used by `eslint` and `typescript-eslint`. Development-only: the
extension bundle contains only the in-repo engine (checked: no `minimatch` or
`eslint` code in the zip), and the patterns come from the repository's own
ESLint configuration. Fixed with an exact `overrides` pin to `minimatch@11.0.8`
instead of npm's suggested semver-major downgrade; ESLint verified to still
enforce its rules. `npm audit`: 0 vulnerabilities; `cargo audit`: none.

## Known limitations (accepted for 0.2.0)

- Experimental breaks sites that need query parameters (search, filters,
  pagination, GET forms) and one-time links with short site-chosen names
  (`?t=`, `?k=`) or generic payment-return names. Escape hatches: Back to
  Clean, site exception, tab pause, "Open link without cleaning".
- A URL protected only by an Experimental-only name (e.g. coupon `code`)
  keeps all parameters, trackers included (navigation rules cannot express
  "skip only the strip rule").
- A server that insists on its query ends in `ERR_TOO_MANY_REDIRECTS`.
- A `POST` answered by a redirect to a `GET` page with a query is stripped.
- Sites can infer Experimental from links arriving without their query.
- All Clean/Strict limitations of 0.1.0 still apply.
