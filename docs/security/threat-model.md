# Threat Model

Scope: the Chromium extension (`apps/browser-extension`), the cleaning
engines (`packages/core`, `crates/untrackable-core`) and the rule set
(`rules/rules.json`).

## Assets

1. **Functionality of the user's links** – sign-ins, password resets,
   purchases, signed downloads must keep working.
2. **The user's browsing data** – URLs visited, copied or cleaned.
3. **Integrity of navigation** – a cleaned link must lead to the same
   destination as the original.
4. **The extension's privileges** – host access to all http(s) sites,
   clipboard write, DNR rules.

## Trust boundaries and adversaries

| Source                                      | Trust                                                            | Examples                                            |
| ------------------------------------------- | ---------------------------------------------------------------- | --------------------------------------------------- |
| Web pages, their DOM and selections         | Untrusted                                                        | Hostile page triggering `copy` events, crafted URLs |
| URLs (navigation, clipboard, context menu)  | Untrusted                                                        | Malformed, huge, IDN homographs, unusual schemes    |
| Content scripts                             | Semi-trusted (run beside hostile pages)                          | Can only query their own tab state                  |
| Extension pages (popup, options, offscreen) | Trusted                                                          | Privileged messages                                 |
| `chrome.storage.local` contents             | Validated on every read                                          | Corrupted or hand-edited settings                   |
| Rule set                                    | Shipped with the extension, validated at load; no remote updates | Future imported lists must use `validateRuleSet`    |

## Threats and mitigations

| #   | Threat                                              | Mitigation                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                           | Residual risk                                                                                                                                                                                                                                                                          |
| --- | --------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| T1  | Cleaning breaks an auth / payment / signed URL      | Protection signals (domains, path keywords and substrings such as `password`, `unsubscribe`, `verif`, parameter names/prefixes/suffixes, `code`+`state`, `expires`+`s`) evaluated before any removal; unknown parameters always kept; Strict mode opt-in; bypass options (exceptions, pause, per-tab pause, one-time bypass)                                                                                                                                                                                                                                                                                                                                                                                                                                                                                         | Heuristics cannot recognise every flow (e.g. a provider signing over `utm_*` with a neutrally named signature on a neutral path). Navigation cleaning cannot see fragments.                                                                                                            |
| T2  | Cleaning changes the destination (scheme/host/path) | Output is the original string with only `&`-separated query/fragment segments removed; scheme, authority and path text are never edited; trailing whitespace exposed by a removal is percent-encoded so parsers cannot strip it; only http(s) is processed; hosts outside the host-name alphabet are rejected. Property tests assert scheme/host/path equality.                                                                                                                                                                                                                                                                                                                                                                                                                                                      | Hosts that are invalid IDNA may be accepted by Chromium's parser (implementation-defined, see spec); the host text is still never modified.                                                                                                                                            |
| T3  | Redirect loops                                      | DNR only redirects when the transformed URL differs (verified in e2e); cleaning is idempotent (property tests); fallback hops strictly shorten the URL and stop at 6+ `&` (guard), keeping chains with server redirects below Chromium's limit. Optional loop helper: never automatic; the popup button only installs a host-scoped one-time bypass and calls `tabs.reload` on the failed tab – Untrackable never navigates to a stored or page-supplied URL and stores only the host; no offer for protected/excepted URLs; once per tab per minute; offers cleared on the next successful top-level navigation, tab close, permission removal and after 10 minutes (alarm)                                                                                                                                         | Without the optional permission, a server that redirects back to a URL _with_ the tracker fails with `ERR_TOO_MANY_REDIRECTS`. The reload the user clicks is a browser-initiated load of the page that failed (same as pressing Reload).                                               |
| T4  | Hostile page abuses the extension                   | `onMessage` checks `sender.id`; privileged messages (`setTabPaused`, `copyText`, `openUnmodified`, `retryLoop`) are accepted only from extension-origin pages (by `sender.url`); content scripts may only send `getTabState` for their own tab and `cleanCopiedLink`; the offscreen clipboard writer only accepts the service worker; messages schema-validated and size-limited. Copy cleaning **does not modify the copy event at all** (no `setData`/`preventDefault`): the content script forwards a link the user copied with the keyboard; the service worker decides with the settings and writes the clean link afterwards. Settings and exceptions never enter the page process, so a page cannot use copies as an oracle (e2e: capture-phase selection swap, `execCommand`, right-click, synthetic events) | A page that already has clipboard-read permission could compare clipboard contents. A **compromised renderer** running code in the content-script world can still write `chrome.storage.local`. Pages can infer the extension server-side from stripped `utm_*` parameters (inherent). |
| T5  | Clipboard manipulation                              | Only after a trusted Ctrl/Cmd+C or Ctrl+Insert keystroke, only when the selection is exactly one http(s) URL, only if the engine returns `cleaned`, and only the engine's cleaned version of that URL is written (a content script cannot make the service worker write arbitrary text); writes rate-limited per tab and serialised; offscreen document closed after each write; orphaned content scripts (extension disabled/updated) detach themselves                                                                                                                                                                                                                                                                                                                                                             | A page can already control what is copied from it; Untrackable never makes this worse.                                                                                                                                                                                                 |
| T6  | XSS in extension pages                              | No `innerHTML`; user data rendered via `textContent`; CSP `script-src 'self'; object-src 'none'`; no `eval`/`Function` (enforced by ESLint)                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                          | —                                                                                                                                                                                                                                                                                      |
| T7  | ReDoS / resource exhaustion on hostile input        | Engine regexes are linear (no ambiguous quantifiers); Rust `regex` and Chromium RE2 are linear-time; percent-decoding only when a key contains `%`; content script ignores selections > 8 KB; explicit actions ignore URLs > 32 KB; messages > 32 KB rejected; exceptions capped at 1,000                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                            | —                                                                                                                                                                                                                                                                                      |
| T8  | Corrupted settings                                  | `sanitizeSettings` coerces every field; exceptions re-validated and punycode-normalised; invalid DNR data is never produced                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                          | —                                                                                                                                                                                                                                                                                      |
| T9  | Supply chain                                        | No runtime dependencies in the extension bundle besides the in-repo engine; dev dependencies pinned exactly with a lockfile; Rust deps locked (`--locked` in CI); GitHub Actions pinned by commit SHA; `npm audit` and `cargo audit` in CI; Dependabot                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                               | Dev tooling (eslint, vitest, esbuild) runs with developer privileges during builds.                                                                                                                                                                                                    |
| T10 | Leakage of sensitive URLs                           | No logging, no network requests, no telemetry; nothing URL-related persisted (see privacy doc); engine never reports parameter values                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                | —                                                                                                                                                                                                                                                                                      |
| T11 | One-time bypass / tab pause leaking or persisting   | Session rules are the only state (allocated ids, kind encoded in id range, tab in `condition.tabIds`); all mutations serialised; "Open link without cleaning" covers that tab until the page has loaded (so redirectors in front of the destination are covered), at most 1 minute (alarm; e.g. downloads never "load"); loop-helper bypass limited to one host; removed on tab close and at browser restart; no blind navigation retry (a second request could consume a one-time link)                                                                                                                                                                                                                                                                                                                             | During that minute, other navigations in the same tab are not cleaned.                                                                                                                                                                                                                 |

## Permissions and justification

Install-time warnings measured with `chrome.management.getPermissionWarningsByManifest`
(Chromium 153): only **"Read and change all your data on all websites"** and
**"Modify data you copy and paste"**. Chromium folds the other warnings into
the host-permission warning.

| Permission                                     | Why                                                                                                                                                 | Verdict                                                                                                     |
| ---------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------- |
| host permissions `http://*/*`, `https://*/*`   | DNR `redirect` actions require host access to the request URL; content script for copy cleaning; reading the active tab's URL for "Copy clean link" | Required; expect an in-depth Chrome Web Store review                                                        |
| `declarativeNetRequest`                        | Navigation cleaning, protection and exceptions                                                                                                      | Required                                                                                                    |
| `storage`                                      | Settings, short-lived session state                                                                                                                 | Required                                                                                                    |
| `contextMenus`                                 | "Copy clean link", "Copy clean page link", "Open link without cleaning"                                                                             | Required                                                                                                    |
| `offscreen`                                    | MV3 service workers have no DOM; clipboard writes use an offscreen document                                                                         | Required                                                                                                    |
| `clipboardWrite`                               | `execCommand('copy')` in the offscreen document (verified: without it the write fails)                                                              | Required for copy cleaning, context menu, shortcut and popup copy. Could become optional in a later version |
| `alarms`                                       | End a timed pause, expire one-time bypasses and loop offers                                                                                         | Required                                                                                                    |
| `webNavigation` (**optional**, off by default) | Redirect-loop helper; only top-level `ERR_TOO_MANY_REDIRECTS` errors and top-level commits (to clear an offer) are used                             | Optional; its warning is already covered by the host permission                                             |

Not requested: `tabs`, `webRequest`, `scripting`,
`cookies`, `history`, `clipboardRead`, `declarativeNetRequestFeedback`.

## Security assumptions

- Chromium enforces extension isolation, CSP and DNR semantics as documented.
- The user's browser profile is not compromised.
- Rules shipped with a release have been reviewed; there is no remote rule
  download in v0.1.
