# Threat Model

Scope: the Chromium extension (`apps/browser-extension`), the cleaning
engines (`packages/core`, `crates/untrackable-core`) and the rule set
(`rules/rules.json`).

## Assets

1. **Functionality of the user's links** – sign-ins, password resets,
   purchases, signed downloads must keep working.
2. **The user's browsing data** – URLs visited, copied or cleaned.
3. **Integrity of navigation** – a cleaned link must lead to the same
   destination as the original.
4. **The extension's privileges** – host access to all http(s) sites,
   clipboard write, DNR rules.

## Trust boundaries and adversaries

| Source                                      | Trust                                                            | Examples                                            |
| ------------------------------------------- | ---------------------------------------------------------------- | --------------------------------------------------- |
| Web pages, their DOM and selections         | Untrusted                                                        | Hostile page triggering `copy` events, crafted URLs |
| URLs (navigation, clipboard, context menu)  | Untrusted                                                        | Malformed, huge, IDN homographs, unusual schemes    |
| Content scripts                             | Semi-trusted (run beside hostile pages)                          | Can only query their own tab state                  |
| Extension pages (popup, options, offscreen) | Trusted                                                          | Privileged messages                                 |
| `chrome.storage.local` contents             | Validated on every read                                          | Corrupted or hand-edited settings                   |
| Rule set                                    | Shipped with the extension, validated at load; no remote updates | Future imported lists must use `validateRuleSet`    |

## Threats and mitigations

| #   | Threat                                              | Mitigation                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                        | Residual risk                                                                                                                                                                                                                                                                                                                                                                                                              |
| --- | --------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| T1  | Cleaning breaks an auth / payment / signed URL      | Protection signals (domains, path keywords and substrings such as `password`, `unsubscribe`, `verif`, parameter names/prefixes/suffixes, `code`+`state`, `expires`+`s`) evaluated before any removal; unknown parameters always kept; Strict mode opt-in; bypass options (exceptions, pause, per-tab pause, one-time bypass)                                                                                                                                                                                                                                                                                                      | Heuristics cannot recognise every flow (e.g. a provider signing over `utm_*` with a neutrally named signature on a neutral path). Navigation cleaning cannot see fragments.                                                                                                                                                                                                                                                |
| T2  | Cleaning changes the destination (scheme/host/path) | Output is the original string with only `&`-separated query/fragment segments removed; scheme, authority and path text are never edited; trailing whitespace exposed by a removal is percent-encoded so parsers cannot strip it; only http(s) is processed; hosts outside the host-name alphabet are rejected. Property tests assert scheme/host/path equality.                                                                                                                                                                                                                                                                   | Hosts that are invalid IDNA may be accepted by Chromium's parser (implementation-defined, see spec); the host text is still never modified.                                                                                                                                                                                                                                                                                |
| T3  | Redirect loops                                      | DNR only redirects when the transformed URL differs (verified in e2e); cleaning is idempotent (property tests); fallback hops strictly shorten the URL and stop at 6+ `&` (guard), keeping chains with server redirects below Chromium's limit; the optional loop helper never navigates automatically (an extension-initiated navigation would bypass SameSite/Referer/Fetch-Metadata CSRF defences), retries only on an explicit click, once per tab per minute, bypassing only the failing host                                                                                                                                | Without the optional permission, a server that redirects back to a URL _with_ the tracker fails with `ERR_TOO_MANY_REDIRECTS`; very long redirect chains that each add new trackers can still reach the limit. The explicit retry itself is a browser-initiated navigation to the URL the page looped on (the user sees the host before clicking).                                                                         |
| T4  | Hostile page abuses the extension                   | `onMessage` checks `sender.id`; privileged messages (`setTabPaused`, `copyText`, `openUnmodified`) are accepted only from extension-origin pages (by `sender.url`); content scripts may only query their own tab; the offscreen clipboard writer only accepts the service worker; messages schema-validated and size-limited; copy cleaning only acts on a trusted copy event directly after a trusted Ctrl/Cmd+C or Ctrl+Insert keystroke whose selection is unchanged (once per keystroke; right-clicks do not count), so page scripts cannot use `execCommand('copy')`, synthetic events or context-menu handlers as an oracle | A page can still observe the result of the user's own copy keystroke for whatever it had selected beforehand (one bit per keystroke). A **compromised renderer** running code in the content-script world can still write `chrome.storage.local` (Chromium offers no per-context access level for it), e.g. turn cleaning off. Pages can also infer the extension server-side from stripped `utm_*` parameters (inherent). |
| T5  | Clipboard manipulation                              | Copy handler only acts on trusted copy events, only when the selection is exactly one http(s) URL **and** the engine returns `cleaned`; `cut` and rich text untouched; offscreen clipboard writes only after explicit user actions, serialised, document closed after each copy                                                                                                                                                                                                                                                                                                                                                   | A page can already control what is copied from it; Untrackable never makes this worse.                                                                                                                                                                                                                                                                                                                                     |
| T6  | XSS in extension pages                              | No `innerHTML`; user data rendered via `textContent`; CSP `script-src 'self'; object-src 'none'`; no `eval`/`Function` (enforced by ESLint)                                                                                                                                                                                                                                                                                                                                                                                                                                                                                       | —                                                                                                                                                                                                                                                                                                                                                                                                                          |
| T7  | ReDoS / resource exhaustion on hostile input        | Engine regexes are linear (no ambiguous quantifiers); Rust `regex` and Chromium RE2 are linear-time; percent-decoding only when a key contains `%`; content script ignores selections > 8 KB; explicit actions ignore URLs > 32 KB; messages > 32 KB rejected; exceptions capped at 1,000                                                                                                                                                                                                                                                                                                                                         | —                                                                                                                                                                                                                                                                                                                                                                                                                          |
| T8  | Corrupted settings                                  | `sanitizeSettings` coerces every field; exceptions re-validated and punycode-normalised; invalid DNR data is never produced                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                       | —                                                                                                                                                                                                                                                                                                                                                                                                                          |
| T9  | Supply chain                                        | No runtime dependencies in the extension bundle besides the in-repo engine; dev dependencies pinned exactly with a lockfile; Rust deps locked (`--locked` in CI); GitHub Actions pinned by commit SHA; `npm audit` and `cargo audit` in CI; Dependabot                                                                                                                                                                                                                                                                                                                                                                            | Dev tooling (eslint, vitest, esbuild) runs with developer privileges during builds.                                                                                                                                                                                                                                                                                                                                        |
| T10 | Leakage of sensitive URLs                           | No logging, no network requests, no telemetry; nothing URL-related persisted (see privacy doc); engine never reports parameter values                                                                                                                                                                                                                                                                                                                                                                                                                                                                                             | —                                                                                                                                                                                                                                                                                                                                                                                                                          |
| T11 | One-time bypass / tab pause leaking or persisting   | Session rules are the only state (allocated ids, kind encoded in id range, tab in `condition.tabIds`); all mutations serialised; removed on tab close, on completion of the bypassed load, after a 1-minute timeout (downloads), and at browser restart                                                                                                                                                                                                                                                                                                                                                                           | A one-time bypass also covers redirects within that page load (intended).                                                                                                                                                                                                                                                                                                                                                  |

## Permissions and justification

| Permission                                     | Why                                                                                                                                                 | Warning shown to users                                             |
| ---------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------ |
| `declarativeNetRequest`                        | Navigation cleaning, protection and exceptions                                                                                                      | "Block content on any page"                                        |
| host permissions `http://*/*`, `https://*/*`   | DNR `redirect` actions require host access to the request URL; content script for copy cleaning; reading the active tab's URL for "Copy clean link" | "Read and change all your data on all websites"                    |
| `storage`                                      | Settings                                                                                                                                            | none                                                               |
| `contextMenus`                                 | "Copy clean link", "Copy clean page link", "Open link without cleaning"                                                                             | none                                                               |
| `offscreen`                                    | MV3 service workers have no DOM; clipboard writes use an offscreen document                                                                         | none                                                               |
| `clipboardWrite`                               | Required for `execCommand('copy')` in the offscreen document (verified: without it the write fails)                                                 | "Modify data you copy and paste"                                   |
| `webNavigation` (**optional**, off by default) | Automatic redirect-loop recovery; only `onErrorOccurred` for top-level `ERR_TOO_MANY_REDIRECTS` is used                                             | "Read your browsing history" (shown only when the user enables it) |
| `alarms`                                       | End a timed pause automatically                                                                                                                     | none                                                               |

Not requested: `tabs`, `webRequest`, `scripting`,
`cookies`, `history`, `clipboardRead`, `declarativeNetRequestFeedback`.

## Security assumptions

- Chromium enforces extension isolation, CSP and DNR semantics as documented.
- The user's browser profile is not compromised.
- Rules shipped with a release have been reviewed; there is no remote rule
  download in v0.1.
